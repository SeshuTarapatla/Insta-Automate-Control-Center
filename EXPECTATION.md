The goal of this project is to build a sophisticated Control Center like Windows App in Flutter.

So what is this control center for?
I have a data scraping project called `Insta-Automate` this is a comprehensive project written in python that has prefect flows. These flows each has its own task. Their objective is that they scrape data from Instagram via ADB controlled device. And saves the data in a Postgres db and screenshots like images at a local directory `IA_DIR` as variable. For my laptop it is `C:\Users\seshu\Pictures\insta-automate` why I say for my laptop is that this project is actually supposed to build as a docker image (via a typer command called `ia build`, you can check the source code). And then that docker image is used to deploy a helmchart with 2 pods defined. So this control center is for that project which is currently fully backend. I'm trying to create a app for this so that I have an UI that way I can see and control stuff much easier.

Current complexities?
This is a very complex question due to the complexity of the `Insta-Automate` project itself. I will tell you the complexity and the way we are trying to solve this via this control center.
1. Limits: Since this project is a data scraping project using prefect flows I should respect and apply strict limits on daily runs. For example there are flows like `entity_scan` which is supposed to scan followers from profiles, likes from posts and reels. I can't keep on scraping indefinitely right so I ave strict limits on how many profiles/reels/posts we can scrape per day. There are similar limits for `entity_follow`: Number of profiles I can follow per day. `entity_scrape`: Number of profiles we can scrape per day. Don't get confused with entity_scan and entity_scrape cause scan is like scanning for likes and followers while scrape is like scraping a single profile of its data like posts count, followers count, following count, bio etc. There are currently hard coded in the app and I lose dynamic control over them. Since they are hard coded everytime I change something I have to commit and then run ia build (as ia build builds the image from the git repo not local), undeploy helmchart and then deploy it.
2. Trigger Delay: Even though we have limits per day we have to maintain some delay between runs right like if my goal is to scrape 100 profiles per day. I scrape 10 per run and wait for 30mins for the next run. Similar delays and conditions per next run is there in flows. These delays are also hardcoded
3. AI Inference: There is an flow called `entity_classify`. This flows goal is to take an fixed size image input and then infer the local ai that just returns male or female. There is a script to run local qwen-3-vl model via llama and also an class that helps to communicate with the AI and fetch responses. But if you remember our service runs on local kubernetes which is provided by Rancher Desktop, but running ai model locally requires GPU hence the service runs on windows and exposes an endpoint which can be called from the pod.
4. ADB host: Since we are actually scraping using an android tool we need to have an adb server running on 0.0.0.0. Why 0.0.0.0 is that same kubernetes networking. The android device I connect will be connected to windows hence the android adb should run on windows exposed to pod.
5. Core Windows services: If you see the core services that runs on windows like VL server for model and ADB service. I need to manually start them as pods are started by rancher k3s but these services I'm responsible to start right. hence the simplest way I did is I created a shortcut with this command `C:\Users\seshu\AppData\Local\Microsoft\WindowsApps\wt.exe adb -a start-server ; D:\Coding\Insta-Automate\.venv\Scripts\python.exe D:\Coding\Insta-Automate\scripts\start_vl_server.py ; D:\Coding\wsl-bridge\.venv\Scripts\wsl-bridge.exe` and put it in startup folder of windows. This starts a wt.exe windows terminak with adb server in the background, vl server for qwen model service and wsl-bridge as custom python api service written in fastapi that provide bridge services between local machine and wsl.
6. What is WSL Bridge: When I'm running this flows they control android device using python uiautomator2. Now when things are happening I wish to see them via Laptop screen. hence I have wrote a simple endpoint /scrcpy which is supposed to provide SCRCPY services when flows call the endpoint the windows machine recognises the request and starts a scrcpy session which mirrors the android phone to laptop. For now this is the only service it provides but I initially thought of it as expanding bridge with new services or endpoints added.
7. Even though prefect is exposed to my machine via localhost from k3s. I need to see the ui in browser for flows and everytime and have to manually change/navigate to new flowruns manually.
8. I have an other flutter project which is for mobile called `Insta-Automate-Client`. The IA_DIR is actually synced with android using `Syncthing` app and then I use the app to review images, move them for next flow stage run or delete them. I also use this to update some of the limits and trigger switches which are present as `config.env` in IA_DIR. And since this is syncthing based there is a delay and also this app doesnt have any notifications.
For now these are the complexities I can think of & I'll update if I find any new
9. Deployment: Everytime anything changes I have to manually run the kubectl commands to undeploy and redeploy.
